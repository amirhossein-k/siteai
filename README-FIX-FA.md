# اصلاح مسیر‌یابی دستیار هوشمند مارلو شاپ

## مشکل

پرسش‌های فارسی مرتبط با ارسال، آدرس تحویل و نام گیرنده ممکن بود به دلیل
طبقه‌بندی واژه‌ای به `out_of_scope` برسند و پاسخ ثابت scope-guard دریافت کنند.

## تغییرات

- نرمال‌سازی حداقلی متن فارسی برای شکل‌های «ی/ي»، «ک/ك» و نیم‌فاصله.
- افزودن الگوهای زمینه‌محور برای زمان و هزینه ارسال، آدرس پستی و تحویل،
  گیرنده، آدرس محل کار، صورتحساب و تغییر آدرس.
- جلوگیری از route شدن پرسش‌های نامرتبطی که فقط واژه‌هایی مثل «آدرس»،
  «ارسال» یا «سفارش» دارند.
- برای سیاست‌های مستندنشده درباره تطابق نام گیرنده با صاحب حساب، ارسال به
  آدرس محل کار یا تغییر آدرس، پاسخ قطعی ساخته نشده است. پاسخ فارسی اعلام می‌کند
  که این شرط در سیاست منتشرشده مشخص نیست و کاربر را به checkout یا پشتیبانی
  هدایت می‌کند.
- پرسش‌های مرتبط با سایت در مسیرهای shipping، policy، navigation و account
  ابتدا به مدل سپرده می‌شوند. دانش رسمی فروشگاه و دستور «حدس نزدن سیاست
  نامستند» داخل prompt مدل قرار دارد. پاسخ محلی فقط fallback زمان در دسترس
  نبودن مدل است و cache این مسیرها همچنان bypass می‌شود.
- برای مسیر `navigation`، fallback راهنمای عمومی حذف شده است. اگر مدل پاسخ
  ندهد، API با وضعیت `503` و metadata برابر `model-unavailable` برمی‌گردد تا
  پاسخ نامرتبط به کاربر نمایش داده نشود.

## فایل‌های تحت تأثیر

- `src/lib/ai-assistant-routing.ts`
- `src/app/api/ai-assistant/route.ts`
- `tests/unit/ai-assistant-routing.test.ts`

## بررسی

تست موردنظر:

```text
npm test -- --run tests/unit/ai-assistant-routing.test.ts
```

در محیط تحویل، `npm` نصب نبود (`/bin/bash: npm: command not found`) و اجرای
Vitest ممکن نشد. برای جبران، یک بررسی آفلاین با Python روی ۷ پرسش مرتبط،
۵ پرسش نامرتبط و metadata مسیر حساس اجرا شد و با موفقیت گذشت.

## محدودیت‌ها

سیاست فعلی فروشگاه درباره اجباری بودن تطابق نام گیرنده و صاحب حساب، ارسال به
آدرس شخص دیگر یا محل کار، و تغییر آدرس پس از ثبت سفارش توضیحی ندارد. این patch
عمداً این موارد را حدس نمی‌زند. همچنین بدون تنظیمات runtime و پاسخ واقعی
provider، invocation مدل ادعا نمی‌شود.

این بسته deploy، commit، push، merge یا restart انجام نمی‌دهد.
